# API-Router Cloud Provider Catalogue and Key Store

## Purpose

Manage user-configured cloud model providers, their encrypted/isolated API key
credentials, automatic upstream model discovery (`discoveredModels`), three-tier
effective model resolution (`discovered -> preset -> none`), local engine model
aggregation (`localModels`), and the `#view-providers` management UI.

## Entry Points

- Persistence (`internal/routerconfig/`):
  - `providers.go`: `CloudProvider`, `ProviderSecret`, `ResolvedCloudProvider`,
    `Store.ListCloudProviders`, `Store.ResolveCloudProvider`
  - `providers_validate.go`: `Store.SaveCloudProvider`,
    `Store.SaveProviderDiscoveredModels`, `validateProvider`,
    `normalizeDiscoveredModels`
  - `providers_write.go`: `Store.DeleteCloudProvider`, `ProviderError`
- HTTP & Probing (`internal/routerservice/`):
  - `providers.go`: `ProviderPreset`, `ProviderCatalog`, `providerPresets`
    (embeds `assets/provider-presets.json` generated by `build/router-presets.go`)
  - `providers_candidates.go`: `probeProvider`, `probeProviderModels`,
    `discoverAndPersistProviderModels`, `checkProviderContext`
  - `providers_api.go`: `handleCloudProviders`, `handleCloudProviderByID`,
    `resolveProviderEffectiveModels`, `listConfiguredLocalModels`
  - `providers_models.go`: `parseProviderModelsBody`, ` probeModelsEndpoint`
- Frontend UI: `internal/routerservice/assets/provider.js` (`#view-providers`,
  `#localProvidersSection`)

## Architecture

### Data Model & Credential Isolation

`routerconfig.CloudProvider` represents a saved cloud provider profile in
`config.json` under `providers[id]`:

```go
type CloudProvider struct {
    ID               string            `json:"id"`
    Name             string            `json:"name"`
    Preset           string            `json:"preset,omitempty"`
    Protocol         string            `json:"protocol"`
    BaseURL          string            `json:"baseUrl"`
    Model            string            `json:"model"`
    DiscoveredModels []string          `json:"discoveredModels,omitempty"`
    AuthMode         string            `json:"authMode"`
    HeaderName       string            `json:"headerName,omitempty"`
    HeaderPrefix     string            `json:"headerPrefix,omitempty"`
    Headers          map[string]string `json:"headers,omitempty"`
    TimeoutMs        int               `json:"timeoutMs"`
    Revision         int               `json:"revision"`
    CredentialRef    string            `json:"credentialRef"`
    KeyPreview       string            `json:"keyPreview"`
    UpdatedAt        string            `json:"updatedAt"`
}
```

- Supported `Protocol` values: `openai_chat`, `openai_responses`,
  `anthropic_messages`, `gemini_native`.
- Supported `AuthMode` values: `bearer`, `x_api_key`, `x_goog_api_key`,
  `custom_header`.
- Plaintext API keys (`ProviderSecret.APIKey`) are stored only in
  `credentials.json` under `providers[credentialRef]`. `config.json` stores only
  `credentialRef` (`cred_<random-hex>`) and a masked `keyPreview`.
- Optimistic concurrency: updates require `Revision` to match the stored record
  (`0` creates a new record; mismatched revisions return `ErrProviderConflict` /
  HTTP `409`).
- Updating a provider with an empty `APIKey` retains the existing
  `credentialRef` and secret while incrementing `Revision`. When a new
  `DiscoveredModels` slice is omitted on update, previously cached
  `discoveredModels` are preserved unless key/endpoint changes trigger a fresh
  discovery probe.

### Automatic Model Discovery & Three-Tier Fallback

1. **Auto-Discovery on Save (`discoverAndPersistProviderModels`)**:
   - When `POST /api/cloud-providers` saves a provider, the service immediately
     probes the upstream models catalogue (`GET /v1/models` or protocol
     equivalent via `probeProviderModels`) with a short timeout.
   - If upstream returns a non-empty model list, the deduplicated model IDs are
     persisted into `CloudProvider.DiscoveredModels` via
     `Store.SaveProviderDiscoveredModelsContext`.
   - When `Model` was omitted during creation, the first discovered model (or
     first preset catalogue model) is automatically selected as the default
     `Model`.
   - Manual `POST /api/cloud-providers/{id}/models` and
     `POST /api/cloud-providers/{id}/check` also persist newly discovered models
     back to `DiscoveredModels`.

2. **Three-Tier `effectiveModels` Resolution (`resolveProviderEffectiveModels`)**:
   `GET /api/cloud-providers` enriches every returned provider item with
   `effectiveModels []string` and `modelSource string` using a strict 3-tier
   fallback:
   - `discovered`: uses `p.DiscoveredModels` when non-empty (ensuring `p.Model`
     is included).
   - `preset`: falls back to the built-in catalogue (`assets/provider-presets.json`
     generated from `build/router-presets.go`) matched by `p.Preset`, `p.ID`, or
     normalized `p.BaseURL`.
   - `none`: returns `[]` (or `[p.Model]` if a single model was manually typed)
     when neither discovered nor preset models exist.

3. **Local Models Aggregation (`localModels`)**:
   - `GET /api/cloud-providers` also returns a top-level `localModels` array
     built by `listConfiguredLocalModels()`.
   - It inspects the local model manifest (`models/manifest.json`) and live
     local engine states (`Ready` / `Installed`) to expose configured on-device
     models (`id: "local/<engine>"`, `engine`, `modelId`, `quantization`,
     `state`, `ready`).

### Deletion Referential Integrity

`Store.DeleteCloudProviderContext` (`DELETE /api/cloud-providers/{id}?revision=N`)
verifies that no application profile (`apps[*].providerId`,
`apps[*].cloud.providerId`, or `apps[*].models`) and no active routing group
(`groups[*].members` or `groups[*].rules`) references `id`. If referenced, it
returns HTTP `400` without mutating state. Otherwise it deletes the provider and
prunes unreferenced secrets from `credentials.json`.

### HTTP Surface & Frontend (`#view-providers`)

- `GET /api/cloud-providers`: returns `{ instanceId, presets, items, localModels }`.
- `POST /api/cloud-providers`: validates and saves a provider, auto-discovers
  models, and returns the enriched provider item (`201` on create, `200` on
  update).
- `DELETE /api/cloud-providers/{id}?revision=<n>`: deletes an unreferenced
  provider.
- `POST /api/cloud-providers/{id}/check` & `POST /api/cloud-providers/check`:
  runs a live upstream probe and updates cached `discoveredModels`.
- `POST /api/cloud-providers/{id}/models` & `POST /api/cloud-providers/models`:
  fetches upstream `/models` and caches `discoveredModels`.
- In `internal/routerservice/assets/provider.js`, `#view-providers` renders the
  cloud provider cards and editor modal, and renders `#localProvidersSection` at
  the bottom of the page as a read-only section displaying configured local
  on-device models (`localModels`) with a quick link to `#view-local` (`Models`)
  when none are installed.
